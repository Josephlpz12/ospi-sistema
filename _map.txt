## Regla de negocio (cómo se va a programar)

Cadena: **cliente → suscripción (servicio) → contrato → factura → pago o mora**.

**Factura vencida (automático, sin FEL)**  
Al listar facturas o al pulsar “Revisar vencidas”: si `fecha_vencimiento < hoy` y el estado es `PENDIENTE`, pasa a `VENCIDA`. No se cobra sola; solo cambia el estado. Se puede crear una alerta `FACTURA_VENCIDA` (usa `alertas.id_factura` si hace falta).

**Pago**  
Se registra contra una factura. Si la suma de `pagos.monto` cubre `facturas.monto`, la factura pasa a `PAGADA`. Eso **no** reactiva el servicio solo: reactivar es un paso explícito (evita reactivar por un abono parcial).

**Mora + multa + suspensión (acción explícita, la que pide OSPI)**  
En una factura `PENDIENTE` o `VENCIDA`, el usuario confirma **Aplicar mora**:

1. Factura → `VENCIDA` (si aún no lo estaba).  
2. Se inserta **multa** (`PENDIENTE`): motivo + monto (el usuario lo captura; por defecto se puede sugerir un % del monto de la factura, p. ej. 10%, editable). Ligada a `id_contrato` e `id_factura`.  
3. **Suscripción** del contrato (o la activa del cliente) → `SUSPENDIDA`.  
4. **Contrato** → `INCUMPLIDO` (o `SUSPENDIDO`).  
5. **Cliente** → `estado = SUSPENDIDO` (ya existe en el CHECK).  
6. Alerta `SERVICIO_SUSPENDIDO`.

Los **proyectos no se cancelan solos** (el trabajo interno puede seguir; el servicio vendido queda cortado). En ficha de cliente se verá “Servicio suspendido”.

**Reactivar** (después de pagar factura y/o multa): acción **Reactivar servicio**: suscripción `ACTIVA`, cliente `ACTIVO`, contrato `VIGENTE` si ya no hay facturas vencidas sin pagar. Multa se puede marcar `PAGADA` al registrar un pago extra o un botón “Condonar” (solo admin, si da tiempo; si no, solo `PAGADA` al capturar el cobro).

No entra: facturación electrónica, recálculo SAT, ni recargos diarios automáticos.

## Backend — endpoints (JWT)

**Catálogo / servicio**

| Método | Ruta | Acción |
|--------|------|--------|
| GET | `/api/productos` | Listar software |
| GET/POST | `/api/clientes/:id/suscripciones` | Listar / crear (producto, fechas, `ACTIVA`) |
| PUT | `/api/suscripciones/:id` | Cambiar estado a mano (`ACTIVA` / `SUSPENDIDA` / `CANCELADA`) |

**Contrato y cobro**

| Método | Ruta | Acción |
|--------|------|--------|
| GET | `/api/contratos?id_cliente=` | Listar |
| POST | `/api/contratos` | Cliente + opcional proyecto/suscripción, número, montos, cláusula mora |
| GET | `/api/contratos/:id` | Contrato + facturas + multas |
| GET/POST | `/api/contratos/:id/facturas` | Listar / emitir (`PENDIENTE`, vencimiento) |
| POST | `/api/facturas/revisar-vencidas` | `PENDIENTE` → `VENCIDA` por fecha |
| POST | `/api/facturas/:id/pagos` | Registrar pago; si cubre el monto → `PAGADA` |
| POST | `/api/facturas/:id/mora` | **Mora + multa + suspender** (transacción) |
| POST | `/api/contratos/:id/reactivar` | Revierte suspensión si la deuda está saldada (o con confirmación) |
| PUT | `/api/multas/:id` | `PAGADA` / `CONDONADA` |

**Tablero**

| Método | Ruta | Acción |
|--------|------|--------|
| GET | `/api/monitoreo/proyectos-activos` | Todos con `estados_proyecto.nombre = 'Activo'` |

Cada fila: `id_proyecto`, código, nombre, cliente, **responsable** (`empleados` vía `proyectos.id_responsable`; si es null → “Sin asignar”), **plazo** (`fecha_fin_plan`), **%**, enlace útil (`id` para el front). No filtrar por % ni por fecha: eso sigue en el panel como “Requieren atención”.
